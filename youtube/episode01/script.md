# 第 1 回 台本「AIに毎週ゲームを作らせてみた #1」

構成は `plan.md` のとおりです。

## この台本の使い方

- 「ナレーション案」は、事実の説明だけを書いたたたき台です。自分の言い方に自由に直してください。
- `[kouheiさんの言葉で: ...]` の枠は、kouhei さん本人の感想、反応、判断を入れる場所です。
  ここには、わざと何も書いていません。AI が反応や点数を先に書くと、この企画の一番大事なところがうそになるからです。
- 初見プレイの反応は、録画したときの声をそのまま使うのが一番です。あとから足す声は「あとから振り返ると」のように区別すると、見る人に誠実です。
- 「テロップ」は画面に出す文字、「画面」は映す素材です。

## 8. 裏側: どうやって毎週届くのか（12:00-14:00）

画面: `plan.md` の図、GitHub の PR 一覧、PR のコメント欄

ナレーション案:

> ここで、裏側のしくみを少しだけ紹介します。
> 毎週の作業は、Claude Code の「ルーチン」という、決まった時間に動くしくみで動いています。
> 木曜の朝 3 時 7 分に、Claude がテーマを選んで、ゲームを作ります。
> 自分でテストをして、動画用の録画もして、「このゲームを足していいですか」というお願い、プルリクエストを出してきます。

> 直してほしいところがあったら、僕がコメントを書いて「fix-please」というラベルを付けます。
> すると、次の日の朝 3 時 37 分に、Claude がそのコメントのとおりに直してくれます。

> 大事なのはここからです。
> ゲームを公開するボタンを押せるのは、僕だけです。
> AI はマージも公開もできないように、最初から決めてあります。itch.io に出すときも、僕が承認したときだけ動きます。

> それから、Claude が指示として読むのは、僕が書いたコメントだけです。
> 視聴者のみなさんのコメントや、GitHub に知らない人が書いた文章を、AI が命令として受け取ることはありません。
> 投票は、数だけを数えて使います。

[kouheiさんの言葉で: 1 か月動かしてみて、しくみについて思ったこと。うまくいったこと、困ったこと]

テロップ: 公開ボタンを押すのは人間だけ

メモ: GitHub の画面を映すときは、メールアドレス、通知、secret が映っていないか確かめます。
