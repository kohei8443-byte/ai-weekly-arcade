# youtube（動画の企画とひな形）

「AIに毎週ゲームを作らせてみた」の YouTube 用の資料です。
動画を作るのも、話すのも、公開を決めるのも kouhei です。
ここにあるのは、構成や説明文のたたき台だけです。

> コードはAI（Claude）、絵と音はコードで生成、判断するのは人間（kouhei）

## フォルダの中身

| ファイル | 内容 |
| --- | --- |
| `README.md` | このファイル。シリーズの形とルール |
| `episode01/plan.md` | 第 1 回の構成案 |
| `episode01/script.md` | 第 1 回の台本（kouhei さんの言葉を入れる枠つき） |
| `episode01/titles.md` | タイトル案とサムネイルの文字案 |
| `episode01/description.md` | 概要欄のひな形 |

第 2 回からは `episode01/` をコピーして `episode02/` を作ります。

## 1. シリーズの形

### 本編（長尺）は月に 1 本

- 1 か月分（だいたい 4 本）のゲームを、1 本の動画にまとめます。
- 長さの目安は 12 分から 16 分です。
- 中心になるのは、kouhei がスマホで初めて遊んだときの画面と声です。
- ナレーションも kouhei 本人の声です。合成音声は使いません。
- 動画のタイトルは「AIに毎週ゲームを作らせてみた #番号」の形をそろえます。

### Shorts は本編から 1、2 本

- 本編から切り出して、1 本の本編につき 1、2 本だけ出します。
- `shorts.md` にはゲームごとに台本案がありますが、全部は出しません。その月で一番反応がよさそうなものを選びます。
- Shorts の割合は、チャンネル全体の総再生時間の半分未満におさえます。月に 1 回、YouTube Studio のアナリティクスで確かめます。
- Shorts の最後では、本編へ案内します（関連動画の設定で本編をつなぎます）。

### 1 か月の流れ

| 時期 | すること |
| --- | --- |
| 毎週木曜の朝 | Claude の PR が届きます。スマホで初見プレイを録画します（ここが動画の素材になります） |
| 毎週 | 採点とメモを残します。マージか却下かを決めます |
| 月末の週 | 本編の録音と編集をします。`episode01/` のひな形を使います |
| 本編の公開日 | 本編を公開し、固定コメントでお題投票を始めます |
| 公開の 2、3 日後 | Shorts を 1 本出します。もう 1 本出すなら、さらに数日あけます |
| 次の月の初め | 投票の数を数え、kouhei が `NEXT.md` に書きます |

初見プレイの録画は、PR を開いて最初に遊ぶときに必ず撮ります。
2 回目以降の反応は「初見」ではないので、動画の中でもそう伝えます。

## 2. 毎回のコーナー

### 今週のAIバグ

- 初見プレイや QA で見つかった、Claude のおかしな作りを 1 つ紹介します。
- 見せる順番は「バグの画面」「kouhei の反応」「直したあとの画面」です。
- 直した中身は、PR のコメントと `NOTES.md` の変更履歴から拾えます。
- バグがなかった週は「バグなし」と伝えます。わざとバグを作ったり、あったことにしたりはしません。

### 初プレイ採点（4 項目）

初めて遊んだ直後に、kouhei が 5 点満点で付けます。合計 20 点です。

| 項目 | 見るところ |
| --- | --- |
| 面白さ | もう 1 回遊びたくなるか |
| 見た目 | 画面のきれいさ、わかりやすさ |
| 独自性 | どこかで見たゲームのままになっていないか |
| バグ | バグの少なさ（バグがないほど高い点） |

- 点数と理由は、毎回 kouhei が自分で決めます。台本に点数を先に書くことはしません。
- 採点表は画面の右上などに、毎回同じ形で出すとシリーズらしくなります。

### 視聴者スコア挑戦

- 本編の最後に、kouhei のベストスコアを発表します。
- 視聴者はゲームを遊んで、自分のスコアをコメントに書きます。
- 次の回で、上位のスコアをハンドル名と数字だけで紹介します。
- スコアは自己申告なので、証拠は求めません。明らかにおかしな数字は紹介しません。

### お題投票

- 次の月に作るテーマを、3 つか 4 つの候補から選んでもらいます。
- 候補は `BACKLOG.md` の未使用のテーマから kouhei が選びます。
- 投票はコミュニティ投稿のアンケート機能を使うと、数を数えやすいです。【未確認: チャンネルでアンケートが使えるかどうか】
- 結果は「A 24 票、B 11 票」のように、数だけを `NEXT.md` に書きます。

## 3. 視聴者のコメントと AI の関係

- Claude（AI）は YouTube のコメントを読みません。コメントを読むのは kouhei です。
- コメントの中の「こう作って」という提案は、kouhei が読んで、よいと思ったものだけを自分の言葉で `BACKLOG.md` か `NEXT.md` に書きます。
- コメントの文章が、そのまま AI への指示になることはありません。投票は数としてだけ使います。
- このことは固定コメントにも書いておきます（`episode01/pinned-comment.md`）。

## 4. YouTube のポリシーについての注意

### 自動で作った動画は出さない

- 録画ツール（`tools/capture.mjs`）が作る `?demo=1` の動画は、編集の素材です。そのまま投稿しません。
- 自動でアップロードするしくみも作りません。Claude は YouTube に何も投稿しません。
- 毎回、kouhei の声、初見の反応、自分の判断（採点、マージか却下か）を入れます。
- YouTube は 2025 年 7 月 15 日から、収益化のポリシーで「大量生産された、くり返しの多いコンテンツ」を「inauthentic content」として扱っています。
  毎回同じ形で中身の薄い動画を量産すると、収益化の対象から外れるおそれがあります。
  この企画では、本人の声と判断が毎回ちがうことが一番の中身です。
  出典: [Plagiarism Today の解説（2025-07-08）](https://www.plagiarismtoday.com/2025/07/08/youtube-targets-inauthentic-content/)

### AI の開示

- 概要欄に、毎回かならず次の文を入れます。

  > コードはAI（Claude）、絵と音はコードで生成、判断するのは人間（kouhei）

- 動画の中でも、冒頭のルール説明で同じことを口で伝えます。
- アップロード画面の「改変または合成されたコンテンツ（altered or synthetic content）」の質問は、現実と見まちがえる映像があるときに **Yes** にするものです。
  ゲーム画面は現実と見まちがえる映像ではないので、ふだんは **No** でよいと考えています。
  ただし、AI で作った本物そっくりの映像や、AI が作った曲を主役にした場面を入れたときは **Yes** にします。最後は kouhei が決めます。
  出典: [YouTube ヘルプ「改変または合成されたコンテンツの使用を開示する」](https://support.google.com/youtube/answer/14328491)
- Anthropic の公式な企画ではないことも、概要欄に書いておきます。

### 子ども向けではない

- この企画は、AI とゲーム制作に興味がある人に向けた動画です。動画ごとに「子ども向けではない」を選びます。
- 金魚やだるまのようなかわいいモチーフでも、子ども向けとして作っているわけではありません。
- ただし、この設定は内容にあわせて正しく選ぶ必要があります。迷ったときは YouTube のヘルプを読んで kouhei が決めます。

### 音楽

使ってよい音は次の 3 つだけです。

1. kouhei が自分で作った曲や音
2. [ZzFX](https://github.com/KilledByAPixel/ZzFX)（MIT License）などでコードから作った効果音。ゲームの中の音も、Claude が書いたコードでその場で鳴らしています。
3. [YouTube オーディオ ライブラリ](https://studio.youtube.com/)の曲。帰属表示（クレジット）が必要な曲は、概要欄の「音楽」の欄に書きます。

- 市販の曲、ほかの動画の音、AI で作曲サービスが作った曲は使いません。
- 使った曲は、概要欄の「音楽」の欄に毎回書きます。

### 画面に映してはいけないもの

GitHub や Claude Code の画面を映すときは、次のものが映っていないか確かめます。

- メールアドレス、通知の中身、ほかのリポジトリの名前
- secret、API キー、トークン（`BUTLER_API_KEY` など）
- 視聴者や他人の名前やアイコン（紹介する許可がないもの）

### 既存の作品

- 動画の中でも、ほかのゲームやアニメのキャラクター、曲、ロゴを使いません。
- 「〇〇みたいなゲーム」と例えるときも、映像や音は使いません。

## 5. 素材の置き場所

| 素材 | 作り方 | 置き場所 |
| --- | --- | --- |
| 初見プレイの画面と声 | kouhei がスマホの画面録画で撮る | kouhei の手元 |
| 縦の動画 1080x1920 | `?demo=1` から `tools/capture.mjs` で作る | GitHub Release のアセット（`wNN-<slug>-vertical.mp4`） |
| 横の動画 1920x1080 | 同上 | 同上（`wNN-<slug>-horizontal.mp4`） |
| GIF | 同上 | 同上（`wNN-<slug>-preview.gif`） |
| サムネイルの元画像 | 同上（1280x720。w01 から w06 は左に文字を置く余白あり、w07 からはゲームの横長の画面そのまま） | 同上（`wNN-<slug>-thumb-base.png`） |

- 表のファイル名は、マージのあとに release ワークフローが作るリリース `wNN-<slug>` のものです。
- PR の確認用の下書きリリース `wNN-<slug>-preview` では、`vertical.mp4` のように先頭の `wNN-<slug>-` が付きません。
- 動画や画像は git に入れません。
- `?demo=1` の動画は、AI が遊んでいる画面です。動画の中で使うときは「AI が遊んでいる画面」とわかるように、テロップで伝えます。
