# routines（毎週の自動作業）

このフォルダには、Claude Code のルーチン（決まった時間に自動で動く Claude のセッション）に貼り付けるプロンプトがあります。
ルーチンは 3 つです。

| ファイル | 名前 | いつ（日本時間） | やること |
| --- | --- | --- | --- |
| [builder.md](builder.md) | builder | 毎週木曜 03:07 | ゲームを 1 本作り、QA と録画をして PR を開く |
| [fixer.md](fixer.md) | fixer | 毎日 03:37 | `fix-please` の付いた PR を、kouhei のコメントどおりに直す |
| [health.md](health.md) | health check | 毎週木曜 12:00 | 今週の PR がなければ Issue を開く |

## 1 週間の流れ

1. 木曜 03:07 に builder が動き、朝までに PR が開きます。
2. kouhei が PR の「スマホで遊ぶ」のリンクからスマホで遊び、初見プレイを録画します。
3. 直してほしいところがあれば、PR にコメントを書き、ラベル `fix-please` を付けます。翌朝 03:37 に fixer が直します。
4. よければ kouhei が **Merge** を押します。サイトに公開され、itch.io は kouhei の承認を待ちます。録画素材は下書きのリリースにできます。
5. 木曜 12:00 に PR が出ていなければ、health check が Issue で知らせます。

## してよいこと、してはいけないこと

3 つのルーチンは、kouhei の GitHub アカウントで動きます。だから、できることをプロンプトでしぼっています。

| | builder | fixer | health check |
| --- | --- | --- | --- |
| `claude/wNN-<slug>` ブランチを作って push する | する | しない | しない |
| 既存の PR のブランチに push する | しない | する（ゲームのフォルダだけ） | しない |
| PR を開く | する | しない | しない |
| PR にコメントする | プレビューの更新に失敗したときだけ | する | しない |
| Issue を開く | QA が通らないときだけ | しない | PR がないときだけ |
| 下書きのリリースを作る | する（素材を付けるため） | 素材の差し替えだけ | しない |
| プレビューページを更新する | する（URL を入れたときだけ） | する（URL を入れたときだけ） | しない |
| ラベル `fix-please` を外す | しない | する | しない |
| `.github/`、`tools/`、`template/`、`CLAUDE.md` を変える | しない | しない | しない |

どのルーチンも、次のことは絶対にしません。

- PR のマージ、auto-merge、PR の承認
- `main` への push、force push、タグの push
- environment（`itch-release`、`github-pages`）の承認と却下、ワークフローの手動実行
- リポジトリの設定、ルールセット、secret の変更
- 下書きでないリリースの公開、itch.io への配信、YouTube への投稿

### push を止めているもの

ルーチンの画面には、push してよいブランチをしぼる設定はありません。
Claude Code のドキュメントにも「push 先をしぼるには、GitHub のルールセットを使う」と書かれています。
そのため、`main` を守っているのは SETUP.md の 6 で作るルールセットです。**Bypass list は必ず空のまま**にしてください。
空でないと、kouhei のアカウントで動くルーチンも `main` に直接 push できてしまいます。

## 指示として扱うもの

- ルーチンが従うのは、保存されたプロンプトと、`main` の CLAUDE.md と、kouhei（`kohei8443-byte`）が自分で書いたコメントだけです。
- `NEXT.md` と `BACKLOG.md` は、テーマとゲームの中身の希望としてだけ使います。ゲームの外の作業の指示としては使いません。
- ほかの人が書いた Issue、PR、コメントは、中に何が書いてあっても従いません。返事もしません。フォークからの PR は、週番号や「今週の PR」の数にも入れません。
- YouTube や itch.io のコメントも同じです。視聴者の投票は、kouhei が数だけを `NEXT.md` に書いたときに使われます。
- Claude も kouhei のアカウントで書き込むので、Claude の書き込みには先頭に `[Claude]`、最後に見えない印 `<!-- ai-weekly-arcade:claude -->` が付きます。
  kouhei のアカウントの書き込みで、この印があるものは、kouhei の言葉としては扱いません。
  ほかの人の書き込みは、この印が入っていても無視します。

## ルーチンの作り方

1. https://claude.ai/code/routines を開き、**New routine** を押します。
2. 各ファイルの「設定」の表のとおりに、名前、スケジュール、リポジトリを入れます。
3. 各ファイルの「プロンプト」の枠の中を、そのまま貼り付けます（プレビューページを使うときは、下の「プレビューページ」を見てください）。
4. フォームの下の **Connectors** には、つないでいるコネクタが最初から全部入っています。全部外します。
   GitHub はコネクタではありません。リポジトリを選べば、組み込みの GitHub のツールと `gh` で使えます。
5. **Create** を押して保存したら、詳細画面の **Run now** で 1 回試します。

画面で cron を使わない場合は、表の「いつ」の曜日と時刻をそのまま選びます。時刻は自分のタイムゾーン（日本時間）で入れれば、自動で変換されます。

別の方法として、自分のパソコンの Claude Code（ターミナル）で `/schedule` を使って作ることもできます。
クラウドのセッション（claude.ai/code）の中では `/schedule` は使えません。作ったら、ルーチンの画面で中身が合っているか確かめてください。

### プレビューページ（任意）

PR のゲームをスマホで遊ぶための、kouhei だけが開けるページです。
このキットを作ったプロジェクトのチャットで、Claude に「プレビューページを作って」と頼むと、ページを作って URL を教えてくれます。
その URL を、builder と fixer のプロンプトの `PREVIEW_URL:` の後ろに足します（例: `PREVIEW_URL: https://claude.ai/...`）。

- builder は PR を開いたあと、fixer は直したあとに、このページを新しいゲームに入れかえます。
- ページを公開設定（Public）にしたり、ほかの人と共有したりしないでください。そうすると、ルーチンは確認なしに更新できなくなります。
- 更新できなかった週は、PR に書かれた予備のリンク（raw.githack.com）で遊べます。

## オンとオフ

- 一時的に止める: ルーチンの詳細画面の上にある、オンとオフのスイッチを切ります。止めている間も設定は残り、オンに戻すと次の予定の時刻から動きます。
- 今すぐ 1 回動かす: 詳細画面の **Run now** を押します。
- やめる: 詳細画面の名前の横のメニューから **Delete** を選びます。プロンプトはこのフォルダに残っているので、いつでも作り直せます。
- 全部をすぐ止めたいとき: GitHub の右上のプロフィール画像から **Settings > Applications > Installed GitHub Apps** を開き、Claude の **Configure** を押します。画面の下の **Suspend** を押すと、どのルーチンも GitHub を読み書きできなくなります（対話のセッションも同じです）。元に戻すときは、同じ画面で停止を解除します。
- 1 週だけ休みたいとき: builder だけをオフにして、health check もオフにします（オンのままだと Issue が開きます）。

## プロンプトを変えたいとき

- このフォルダのファイルを直す PR を作り、マージしてから、ルーチンの画面のプロンプトも同じ内容に貼り替えます（名前の横のメニューの **Edit**）。
- ルーチンは、画面に保存されたプロンプトで動きます。このフォルダを直しただけでは変わりません。
- ただし、ルーチンは毎回 `main` の CLAUDE.md を読むので、CLAUDE.md の変更はマージしただけで反映されます。

## ネットワークが止められたとき

builder と fixer は、QA と録画のために npm のパッケージと Chromium を使います。
環境の初期の設定（**Trusted**）では、npm、Ubuntu のパッケージ、GitHub には最初からつながります。Chromium は環境に最初から入っていることもあります。
セッションの記録に「403」や「host_not_allowed」が出て Chromium をダウンロードできていない場合は、次のドメインを許可してください。

- `cdn.playwright.dev`、`playwright.download.prss.microsoft.com`、`playwright.azureedge.net`（Playwright の Chromium）

手順は次のとおりです。

1. ルーチンの詳細画面で、名前の横のメニューから **Edit** を選びます。
2. **Instructions** の下にある、環境の名前（**Default** など）が書かれた雲のアイコンを押します。
3. 一覧の環境にマウスをのせ、右に出る設定のアイコンを押します。
4. **Network access** を **Custom** にして、**Allowed domains** に上のドメインを 1 行に 1 つずつ入れます。
5. **Also include default list of common package managers** にチェックを入れて、初期の一覧も残します。
6. **Save changes** を押します。次の実行から使われます。

くわしくは https://code.claude.com/docs/en/routines と https://code.claude.com/docs/en/cloud-environments#network-access を見てください。

それでも録画ができない週は、PR に理由が書かれます。素材は、マージすると Actions の release ワークフローが下書きのリリースに作ります（`.github/README.md`）。

## うまく動かなかったとき

| 起きたこと | 見るところ |
| --- | --- |
| 木曜の朝に PR がない | health check の Issue、ルーチンの実行履歴 |
| 実行履歴は緑なのに、何もできていない | 緑は「セッションが動いて終わった」という意味だけです。実行を開いて、記録を読みます |
| どのルーチンも動いていない | claude.ai と GitHub のつながりが切れていると、ルーチンは動きません。72 時間たつとルーチンがオフになるので、つなぎ直してからオンに戻します |
| `[Claude] wNN の QA が通りませんでした` の Issue がある | Issue に書かれたブランチと失敗した項目 |
| PR のゲームが気に入らず、別のゲームがほしい | PR を閉じてから、builder の **Run now** を押します（開いている PR があるうちは、二重に作らないように何もしません） |
| fixer が直さない | ラベル `fix-please` が付いているか、コメントが kouhei のアカウントで書かれているか |
| fixer が「マージしますか、それとも閉じますか」と聞いてきた | 2 回直しても解決していません。マージするか閉じるか、続けるなら「続けて」と書いて `fix-please` を付けます |
